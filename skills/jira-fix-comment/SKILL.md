# jira-fix-comment

## 完成目標

向讀者清楚說明最終根因、修改內容與驗證結果；可追溯至實際 spec／diff／commit，不把每輪失敗探索搬進留言。

## 驗收與邊界

範圍與票號一致，涵蓋相關 repo 的改動；有 commit 才列真實 hash，未驗證事項明示。依專案格式組織標題、根因、修改位置、驗證及連結，不固定業務範例或最低欄位數。

僅在已獲明確留言授權時使用 connector 張貼，否則交付草稿。已有授權不重複確認。核對實際回傳的留言結果；回應不確定先查現有留言，避免盲目重試重複發布。報告完成本身不授權留言。
