# Plan conflict discussion

適用於共用 plan board 的任務。先讀當前 board 的 Locked Contract、Mutable Progress、專案規範及本次使用者授權；本 skill 不擴張它們。沒有 COORD 角色時，先由 board 持有者指定協調者，不讓多個任務各自發布互相矛盾的裁定。

## 升級路徑

1. **L0 任務內處理**：契約或已核對證據能唯一回答時，執行者自行決定並記錄依據。
2. **L1 回報 COORD**：跨任務資源／假設衝突、契約與現況不符、兩案皆合理或依賴任務阻擋時，提供 task/claim ID、問題、至少兩案及各自證據、傾向與受阻工作。使用環境可用的 session 通訊方式；若不可用，寫入 board 進度並通知場控。
3. **L2 場控討論**：COORD 獨立核對原始證據；現有規範不能裁定且不涉及新授權時，才使用可用的唯讀獨立第二意見。給對方最少必要的契約、證據與問題，不傳憑證、個資或整份對話。模型／CLI 依當前環境選擇，執行權限須為唯讀；保存原始輸出或可重現的紀錄。第二意見是參考，COORD 記錄採納或不採納的證據理由。
4. **L3 請使用者裁定**：若要改 Locked Contract、驗收範圍、board 結構、跨 repo 介面，或做本次任務未授權的外部發布、破壞性操作，先整理已做檢查、候選方案、影響及一個明確問題。已有明確授權的提交、推送或檔案修改照原任務執行，不重複請示。

第二意見暫時不可用時記錄狀態與錯誤摘要；不要把未取得的意見寫成完成。可繼續不依賴裁定的工作；若裁定確實需要獨立意見或使用者選擇，將問題交給使用者。呼叫或證據不足可修正後有限重試，勿以提高寫入權限繞過唯讀限制。

## 留證與邊界

L1 以後的回報、核對、討論、裁定與影響，寫入各自的 Mutable Progress。使用當前 board 提供的更新介面與併發保護；更新前讀最新版本，失敗後重新讀取並合併，不手改受保護欄位。記錄必要來源與結論即可，不複製完整 transcript。不得以同儕共識或第二意見冒充使用者授權。
