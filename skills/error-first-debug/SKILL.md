# 根因診斷

## 完成目標

說明預期與實際行為、可核對的根因或尚未排除的假設，以及修正的驗證結果。讀碼、重現、日誌、截圖與測試均可用於取證，依資訊缺口選擇，不固定順序。

## 驗收證據

- 引用與問題相關的錯誤訊息、呼叫鏈、資料差異或重現結果；假設與已證實結論分開。票務摘要及附件檔名是線索，不能單獨證明實際功能入口；畫面相關問題核對相關截圖或實際頁面。
- 耗時紀錄包含當時 timeout、觀測時間與完成／逾時／取消狀態。接近上限只能提示可能截尾，不能單憑數值判定逾時；已截尾資料不能當作完整完成耗時。
- 效能結論若需要完整耗時，可依既有日誌或在安全、授權與成本範圍內重測；不能重測時明列限制，不自動提高生產環境上限。
- 在會影響修正選擇時，比較合理的候選資料／服務／查詢路徑，標記已量測與未量測。說明探索範圍，不宣称窮舉所有可能，也不因僅找到一條路徑就認定它唯一。
- 修正效果連結到原問題與相關回歸證據；取證不足時仍可探索或建立重現測試，但不能宣稱根因及修正已確認。

## 按情境使用

資料錯誤要辨別查詢過濾與資料產生責任；例外可從 stack trace 追到實際 getter、規則或呼叫者。常見辨識線索見 [root-cause-patterns.md](root-cause-patterns.md)。

## 知識與範圍

可重用結論依適用知識庫契約蒸餾，保留來源；不因每次 bug fix 就新增業務文件。只讀取任務相關票務附件，對外留言、發布與環境修改沿用使用者授權。
