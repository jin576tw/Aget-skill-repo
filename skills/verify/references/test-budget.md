# 測試預算與驗收

執行前依風險規劃案例：AC、可觀察的預期結果與評分標準、執行方法、證據位置、驗收責任人、模型／effort、次數、時間與成本區間。小型本機檢查可用簡短清單，不強制新增文件或測試。

結果逐項記為通過、失敗、未驗證或明確豁免；必要案例不能以平均分數抵銷失敗。事先定義有意義的門檻，不為所有任務硬套數字分數。

## 帳戶與批次預算

- 本機不額外消耗帳戶額度的檢查可依原授權執行。模型實跑、顧問 CLI、付費 API 等額外消耗額度的測試，先交案例、模型／effort、次數、重試上限與預估成本，每批取得使用者核准後執行；要求顧問審查不等於核准未知成本。
- 優先讀宿主提供的方案、剩餘額度與重置時間，附來源及讀取時間；缺資料請使用者補充，不讀憑證、不付費探測。模型成本包含宿主自動載入的 instructions／skills／工具 context、重複送入與快取讀寫、思考及工具回合；不能只按任務 prompt 長度估算。無可用換算規則時，提供預估 token／呼叫／時間區間並標示金額與額度比例未知；API 定價不得冒充訂閱額度。
- 核准限該批案例、模型、次數與成本上限；實際可觀察用量達預算 80% 回報，上限即停止。不能精準觀察用量時依核准的呼叫／輸出／時間上限控制，不假稱精準追蹤。先確認 CLI 限制是否為可驗證的硬上限；未知時標為估值，若實際超出則如實回報、不自動追加呼叫。新增批次、超額或更昂貴配置須重新核准。

## 任務與計畫驗收

每個 plan-board Task 不論獨立 session、主會話或 subagent 執行，都須在放行前有可驗收的 Acceptance、Tests、Completion Evidence 與驗收責任人（可在 Sign-off 或協調規則指明）。既有欄位可引用 spec；缺標準先補足，locked contract 變更遵循確認與 hash 流程。

執行者交逐項 AC 預期／實際結果、證據位置、基準版本、未測與風險；驗收者核對目前版本，必要時重現。只有文字結論、exit code 或其他任務的結果不足以證明全部 AC。未驗證或失敗維持未完成；使用者明確豁免須記項目、原因、影響、授權依據，保留未驗證標示，不改為通過。

Task completed 不等於計畫完成。全案驗收還須核對計畫完成條件、整合證據、Sign-off，以及無在途工作或未處理 claim；完成任務保留的 claim 是歷史識別，不算在途。機械欄位檢查不證明證據語意正確。
