# verify

## 完成目標

為要求的行為提供真實執行證據與適用限制，區分通過、失敗及無法驗證。

## 驗收

選擇能觸達改動行為的測試、CLI、API 或瀏覽器操作。GUI 與 CSS 可見效果須在實際渲染頁面觀察並作相關斷言；只有 build、讀碼或一張無判斷依據的截圖不足以證明行為正確。整合主張需真實整合證據，mock 僅驗證隔離部分。

使用實際專案的啟動方式、網址、權限及資料，不固定 Angular、4200 或全 API mock。後端或憑證不可用時說明具體缺口並保留已有證據；不以缺口掩蓋實際失敗，也不將未測算通過。

回報操作、預期／實際結果、證據路徑及限制。暫存 fixture 只清理本次建立的內容，不影響使用者資料。
