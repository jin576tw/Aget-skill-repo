# Ask arXiv

將使用者的問題或待核對說法轉成近期、可追溯的研究證據，說明它能支持什麼、不能支持什麼，以及如何在目前任務驗證。使用宿主現有的網頁搜尋／閱讀工具；不新增檢索服務、固定研究 agent 或套件依賴。

## 適用範圍

- 明確呼叫本 skill，或使用者需要研究論據、方法比較、反例、可實作的理論支持時使用。
- `/ask-arxiv` 是使用意圖；實際顯式呼叫名稱依宿主及安裝 namespace，不能只建立此檔就宣稱裸 slash command 已註冊。維持自然語言自動選用。
- 從目前任務取得待判斷的設計、限制與所需證據；上下文已足夠時直接搜尋。除非缺口會改變研究方向，不先增加需求問卷。
- 一般實作不必先找論文；官方 API／版本用法由官方文件核對。研究需求不授權順帶修改產品、安裝工具或對外發文。

## 時效規則

以查詢當天的實際日期計算時間窗，不把年份寫死。使用者指定的時間範圍優先；未指定時：

- 優先搜尋近 **6 個月**，主要採用近 **12 個月**首次提交的論文。
- 當近 12 個月缺乏直接相關證據，才擴大至 **24 個月**；在結果中標示「擴大時間窗」與原因，不默默放寬。
- 超過 24 個月的論文不作為當前建議的實證支持。只有使用者明確要求歷史／奠基研究或核對指定舊論文時才讀取引用，標為「歷史／指定來源」，不混入近期證據。
- 核對 arXiv 摘要頁的 **首次提交日期、最新修訂日期、版本號**。搜尋引擎的爬取日期與最近修訂日期都不能代替首次提交日期；舊作更新版本仍是舊作。
- 優先讀最新可用版本；若核對的是特定版本的數字，明列該版本，並檢查最新版本是否更正或撤回相關結論。版本間的標題、方法與數字不得拼接。
- 近年論文仍可能使用過時模型、軟體版本或不相容環境。方法與任務適配性比新舊排名更重要；不為追求新日期選弱相關來源。
- 沒有符合時效與相關性的證據，直接回報缺口。不得用舊論文、推測或不存在的引用補足數量。

## 搜尋與原文核對

以 arXiv 為研究入口，例如 `site:arxiv.org <問題的英文關鍵字> <年份或方法名>`；可用其原生搜尋。對待驗證主張搜尋支持及反對／失敗條件，避免只找能證明既有方案的關鍵字。日期篩選只是候選篩選，仍逐篇核對摘要頁 metadata。

對真正用來支持結論的論文：

- 原文與版本：開啟摘要頁確認身分與版本，再讀相關 HTML／PDF 的方法、結果、表格或限制段落。只有摘要可讀時標明「僅核對摘要」，不引用其中未能檢查的細節作為確定結論。
- 數值證據：核對數字的分母、任務、資料集、模型／宿主、對照條件、評分方法；區分百分比與百分點、單次與重複試驗、資源消耗與成功率。
- 證據類型：區分理論證明、受控實驗、觀察相關性、benchmark、案例與觀點。記錄影響結論的樣本限制、信賴區間與相反結果；不可將檢索命中率當成實際任務完成率。
- 引用核對：核對被引用的聊天、文章或簡報是否正確對應原文；找不到原文則標為未核實，不沿用其來源代碼或數字。評估的是說法，不為同意使用者而選證據。
- 出版狀態：原文聲明已發表或通過同行審查時，需有可核對的出版資訊；arXiv 收錄本身不等於已完成同行審查。不把作者提供程式碼當成已重現結果。

頁面無法讀取時，可改用同篇 arXiv PDF／HTML 或作者連結的正式版本，並標明實際讀到的版本。網路／工具不可用時回報無法即時核對，不用記憶冒充搜尋結果。找到足以回答問題的證據後停止；篇數隨問題調整，不為湊篇數擴張研究。

## 回答與落地

沿用使用者語言，先回答目前主張獲得支持、部分支持、受到反證，或證據不足。內容深度配合問題，不強制每次產出完整報告。

- 附直接來源連結與必要定位：論文名稱、首次提交日期、實際引用版本、相關章節／表格。對主要引用版本不同於最新版的情況列出修訂日期。引用指向實際核對的版本，不引用搜尋結果頁。
- 將 **原文結果**、**適用限制**、**對目前任務的推論** 分開表達。數字與引文緊鄰來源；不大量複製論文。
- 使用者需要可實作方案時，提出最小變更、保留的要求、適用情境與可觀察的對照驗證。優先重用現有流程／工具，不因論文提出新框架就要求照搬整套系統。
- 驗證至少涵蓋目標成果與可能退步的能力；不能用省 token 抵銷必要要求遺漏，也不能把本地自查說成獨立審查或論文重現。
- 查詢與核對通常直接在對話交付。使用者要求更新計劃／知識庫時才依該工作範圍保存摘要與來源，沿用目標 workspace 的寫入契約；不自動保存整篇論文或聊天紀錄。

## 自查

交付前確認：主要證據符合時間窗；原文身分／版本／數字有對應；有交代會改變決策的限制與反例；沒有把近期、被引用次數多或附程式碼當成可靠性保證；沒有新增與問題無關的工具或流程。
